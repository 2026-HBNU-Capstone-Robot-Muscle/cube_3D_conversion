# 큐브 면 인식 → 3D 모델 변환 프로젝트 컨텍스트 프롬프트

아래 프로젝트의 기존 구현을 존중하면서 기능을 분석·수정·확장해줘. 코드 주석과 사용자 안내는 한국어로 작성하고, 파일을 수정했다면 어떤 파일을 왜 수정했는지 반드시 알려줘.

## 1. 프로젝트 목표

사람 또는 향후 로봇이 3×3 루빅스 큐브를 카메라 앞에서 돌려 보여주면, 프로그램이 여섯 면을 순서대로 인식·캡처하고 54개 스티커의 색상 상태를 3D 큐브로 시각화한다.

- 이번 범위에는 큐브 솔버 연동과 로봇 제어 명령 생성은 포함하지 않는다.
- 현재는 사람이 노트북 내장 카메라 앞에서 큐브를 움직이는 프로토타입 단계다.
- 카메라 입력은 내장 카메라뿐 아니라 향후 휴대폰 IP 스트림 URL도 지원해야 한다.
- Python 3.10 이상을 사용한다.

## 2. 모델

다음 GitHub 저장소의 `cube-detector.pt`를 사용한다.

- 저장소: <https://github.com/2026-HBNU-Capstone-Robot-Muscle/cude-detector>
- 실제 확인된 모델 속성: YOLO OBB, `task='obb'`, 클래스 `names={0: 'side'}`
- 모델은 큐브 면의 위치·회전 사각형만 탐지한다.
- 모델은 색상 분류나 3×3 칸 분할을 하지 않으므로, 모두 후처리로 처리한다.

중요한 한계:

- OBB의 네 꼭짓점은 회전 직사각형이다.
- 카메라가 면을 비스듬히 보면 실제 큐브 면 경계는 사다리꼴이므로 OBB 꼭짓점과 차이가 날 수 있다.
- 현 프로토타입은 큐브 면을 카메라에 최대한 정면으로 보여주는 것을 전제로 한다.
- 추후 정확도 향상 단계에서는 OBB로 ROI를 얻은 뒤 윤곽선·직선(Hough line 등)을 이용해 실제 사다리꼴 꼭짓점을 보정할 수 있다.

## 3. 확정된 파이프라인

1. 카메라 스트림 시작
2. 프레임마다 YOLO OBB로 큐브 면 ROI 탐지
3. 최근 프레임 중심좌표의 움직임으로 정지 상태 판정
4. 정지 상태와 품질 조건을 만족할 때 캡처 후보 생성
5. OBB 꼭짓점으로 원근보정하여 정사각형 면 이미지 생성
6. 3×3 격자로 나누고 각 칸 중앙 영역의 중앙값 BGR 색상 추출
7. F → R → B → L → U → D 순서로 여섯 면 수집
8. 여섯 중심색을 세션 기준색으로 사용해 Lab 공간에서 54칸 색상 분류
9. 색상별 개수가 각각 9개인지 검증
10. 검증 통과 시 `cube_state.json` 생성 후 Three.js 3D 뷰어로 표시

## 4. 핵심 설계 원칙

### 색상 분류

- 고정 RGB/BGR 임계값을 사용하지 않는다.
- 이번 세션에서 캡처한 여섯 면의 중앙 스티커 색을 기준색으로 사용한다.
- 기준색과 모든 스티커 색을 `cv2.COLOR_BGR2LAB`로 Lab 색공간으로 변환한다.
- Lab 유클리드 거리가 가장 가까운 기준색으로 분류한다.
- 각 스티커에 대해 1순위·2순위 거리 차(margin)를 기록해 애매한 칸을 찾는다.
- 색상별 개수가 9개가 아니면 억지로 보정하지 않는다.
- 중심색끼리 Lab 거리가 너무 가까우면 유사 중심색 경고를 낸다.

주의: **색상별 정확히 9개인지**는 여섯 중심색이 모두 확보된 뒤에만 정확히 검증 가능하다. 한 면을 막 캡처한 시점에는 다른 색의 기준색이 없을 수 있으므로 전역 54칸 검증을 할 수 없다.

### 면 순서와 방향

- 캡처 슬롯은 `F, R, B, L, U, D`로 고정 관리한다.
- 화면에 다음에 보여줄 면을 안내한다.
- 정사각형 OBB만으로는 실제 면의 0/90/180/270도 방향을 완전히 알 수 없다.
- `rotation_quarter_turns`의 정의: 원근보정 이미지에 표준 방향을 맞추기 위해 **시계방향으로** 적용해야 하는 90도 회전 횟수(0~3).
- 캡처 확인 화면에서 `0~3`으로 이 값을 보정할 수 있다.

### 꼭짓점 순서(매우 중요)

- 모델 OBB가 준 첫 번째 꼭짓점은 유지한다.
- 단순히 `argsort(angle)`으로 네 점을 재정렬하면 첫 점이 바뀌어 면 방향이 프레임별로 90도 뒤틀릴 수 있으므로 사용하지 않는다.
- 첫 점을 고정한 상태로, 필요할 때 나머지 점의 순서만 뒤집어 핸드니스(시계 방향)를 통일한다.

### 품질 게이트

다음 조건을 통과한 프레임만 캡처 후보가 된다.

- YOLO confidence 이상
- 최소 OBB 면적 이상
- 꼭짓점이 화면 경계에 닿지 않음
- OBB 종횡비가 최소값 이상(정면성의 거친 필터)
- Laplacian variance가 최소 선명도 이상

품질 불량 프레임은 정지 이력을 초기화하므로 자동 캡처되지 않는다.

### 중복 면 방지

- 캡처 후 잠금 상태를 유지하고, 면이 사라지거나 충분히 이동해야 잠금을 해제한다.
- 이는 같은 화면을 연속 캡처하는 것을 막을 뿐, 실제로 다른 큐브 면임을 보장하지는 않는다.
- 새 면의 중심 Lab 색이 기존 슬롯 중심색과 너무 유사하면 중복 의심 경고를 낸다.
- 자동 저장 모드에서는 중복 의심 면을 저장하지 않는다.
- 수동 확인 모드에서는 `A`를 한 번 더 눌러 강제 저장할 수 있다.

## 5. 현재 파일 구성과 구현 상태

### `face_tracker.py`

- `CubeFaceDetector`: `cube-detector.pt` YOLO OBB 로드 및 최고 confidence 면 탐지
- `FaceDetection`: `corners`, `center`, `confidence` 보관
- `StationaryCaptureTrigger`: 중심좌표 이력 기반 정지 판정 및 잠금/해제
- `CaptureQualityGate`: confidence, 면적, 화면 경계, 종횡비, Laplacian 선명도 검사
- `FaceTracker.process(frame)`: 탐지 → 품질 게이트 → 정지 트리거를 합친 `FrameObservation` 반환
- 캡처 트리거와 품질 판정은 향후 로봇 신호 기반으로 교체할 수 있게 분리되어 있다.

### `color_extract.py`

- `order_corners`: 첫 꼭짓점 유지 + 핸드니스만 통일
- `warp_face`: OBB 네 꼭짓점으로 Homography 원근보정
- `split_grid_and_sample`: 3×3 칸의 테두리를 제외한 중앙 약 72% 영역에서 BGR 중앙값 추출
- `extract_face_colors`: 보정 이미지와 9칸 BGR 값 반환
- `draw_sampling_grid`: 테스트·확인용 3×3 그리드 표시

### `camera_source.py`

- `OpenCVCameraSource`: 카메라 인덱스(예: `0`)와 IP 스트림 URL을 같은 인터페이스로 처리
- 연결 끊김 시 재연결을 시도한다.
- `parse_camera_address`로 문자열 입력을 카메라 번호 또는 URL로 변환한다.

### `cube_state.py`

- `FACE_ORDER = ("F", "R", "B", "L", "U", "D")`
- `FaceCapture`: 원본 프레임, 보정 면 이미지, OBB 꼭짓점, 9개 BGR/Lab, confidence, 회전값, 시간 등 보관
- `CubeSession`: 슬롯별 캡처 저장, 중복 중심색 경고, 재촬영용 `remove_capture`, Lab 분류와 검증 수행
- `CaptureArchive`: 면별 `original.png`, `warped.png`, `metadata.json` 저장
- 검증 항목: 색상별 개수, 애매한 스티커, 서로 가까운 중심색
- `ValidationReport.is_valid`는 현재 색상별 개수 오류와 유사 중심색이 없을 때만 참이다. 애매한 칸은 경고로 기록하지만 단독으로 막지는 않는다.

### `main.py`

- 전체 카메라 루프와 F→R→B→L→U→D 진행 UI 담당
- 기본값은 자동 저장 모드다.
- `--confirm-capture` 옵션을 주면 캡처 후보마다 확인 창을 표시한다.
  - `0~3`: 회전값 변경
  - `A` 또는 Enter: 저장
  - `R`: 저장하지 않고 같은 면 재촬영
- `--min-confidence`, `--min-area`, `--min-aspect`, `--min-sharpness`로 품질 임계값을 조절할 수 있다.
- 6면 수집 후 색상별 9개 검증을 한다.
- 검증 실패 시 `cube_state.json`을 저장하지 않으며, 오류가 난 면 키(`B`, `L` 등)를 눌러 그 면을 제거하고 재촬영할 수 있다.
- 검증 성공 시 `cube_state.json`을 저장한다.
- 검증 성공 화면에서 `Q`를 누르면 3D 뷰어 로컬 서버와 브라우저를 실행한다.
- `--viewer-port`로 기본 포트 8000을 변경할 수 있다.

### `viewer.html`

- Three.js 기반 3D 큐브 뷰어
- `captures/cube_state.json`을 기본으로 읽는다.
- 파일 선택으로 다른 `cube_state.json`도 직접 불러올 수 있다.
- 54개 스티커와 F/R/B/L/U/D 중심색 범례를 보여준다.
- OrbitControls로 마우스 회전, 휠 확대/축소, 오른쪽 드래그 이동을 지원한다.
- Three.js는 CDN에서 로드되므로 최초 로딩에는 인터넷 연결이 필요하다.

### `viewer_server.py`

- `viewer.html`과 `captures` 폴더를 제공하는 로컬 HTTP 서버
- 기본 URL: `http://127.0.0.1:8000/viewer.html`

### 테스트 파일

- `test_face_tracker.py`: 실시간 OBB·정지·품질 게이트 확인
- `test_color_extract.py`: 원근보정, 3×3 그리드, BGR 샘플 확인
- `test_camera_source.py`: 카메라 입력 확인(선택)
- `test_cube_state.py`: 합성 데이터 기반 Lab 분류·회전·검증 확인

## 6. 실행 방법

### 전체 스캔

```powershell
python main.py --output captures_run1
```

수동 회전/저장 확인까지 사용하려면:

```powershell
python main.py --output captures_run1 --confirm-capture
```

품질 게이트가 너무 엄격하면 예시처럼 조절할 수 있다.

```powershell
python main.py --min-area 8000 --min-aspect 0.45 --min-sharpness 50
```

### 3D 뷰어만 수동 실행

```powershell
python viewer_server.py
```

브라우저에서 다음 URL을 연다.

```text
http://127.0.0.1:8000/viewer.html
```

## 7. 현재 알려진 제한과 권장 개선 순서

1. **면별 즉시 재촬영 자동화**
   - 지금은 품질 게이트가 불량 프레임을 자동 거절한다.
   - 이후에는 원근보정 뒤 3×3 샘플 자체의 품질(너무 어두움, 채도 부족, 칸 간 과도한 혼합 등)을 추가 검사해 실패 시 다음 면으로 넘어가지 않도록 개선할 수 있다.
   - 전역 색상별 9개 검증은 반드시 여섯 면 기준색을 모은 뒤 수행한다.

2. **다중 프레임 색상 샘플링**
   - 정지 구간의 한 프레임만 쓰지 말고 여러 프레임의 9칸 색을 모아 중앙값으로 합치면 조명 노이즈·자동 노출 변화에 강해진다.

3. **카메라 설정 고정**
   - 가능하면 자동 화이트밸런스·자동 노출을 고정하고, 균일한 조명에서 촬영한다.

4. **실제 사다리꼴 꼭짓점 보정**
   - OBB 내부 윤곽선/직선 검출을 추가해 기울어진 면의 원근보정 정확도를 개선한다.

5. **방향 보정 UX 개선**
   - 현재는 사용자가 확인 창에서 0~3을 선택한다.
   - 실제 큐브의 면 전환 규칙 또는 시각 마커를 이용하면 방향 보정을 자동화할 수 있다.

## 8. 작업 시 주의사항

- 기존 사용자의 변경을 지우거나 `git reset --hard` 같은 파괴적 명령을 사용하지 않는다.
- 워크스페이스 코드와 사용자가 Desktop에서 실행하는 복사본은 별개일 수 있다. 수정 후 사용자가 Desktop에서 실행한다면 수정된 파일을 복사해야 한다.
- 변경 후에는 관련 문법 검사 또는 테스트를 실행하고 결과를 간단히 보고한다.
- 실제로 구현되지 않은 기능을 UI 문구나 설명으로 약속하지 않는다.
