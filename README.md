# YOLO OBB 기반 3×3 큐브 상태 인식

카메라 영상에서 3×3 루빅스 큐브의 각 면을 인식하고, 54개 스티커의 색상 상태를 JSON 데이터로 저장하는 Python 프로젝트입니다.

현재는 사람이 큐브를 카메라 앞에서 돌려 보여주는 프로토타입입니다. 추후 큐브 솔버, 로봇 손 제어, 강화학습 제어 모듈의 입력 데이터로 활용하는 것을 목표로 합니다.

## 주요 기능

- YOLO OBB 모델로 큐브 면의 위치와 회전 사각형 탐지
- `Space` 키를 눌러 원하는 프레임을 직접 캡처하는 수동 촬영 모드
- 신뢰도, 면적, 화면 잘림, 기울기, 블러 품질 검사
- OBB 꼭짓점 기반 원근보정 및 3×3 격자 분할
- 각 스티커 중앙 영역의 BGR 중앙값 색상 추출
- 캡처된 6개 중심색을 기준으로 한 Lab 색공간 색상 분류
- 색상별 정확히 9개인지 검증하고, 오류 시 상태 파일 저장 방지
- F → R → B → L → U → D 순서 및 큐브 회전 안내 표시
- 캡처 원본, 보정 이미지, 9칸 BGR/Lab 값, OBB 메타데이터 보존
- 선택 사항: Three.js 기반 3D 상태 뷰어

## 시스템 흐름

```text
카메라 영상
  → Space 키 입력으로 현재 프레임 캡처
  → YOLO OBB로 큐브 면 탐지
  → 캡처 품질 검사
  → 원근보정 및 3×3 분할
  → 9칸 색상 추출
  → 6면 중심색 기반 Lab 색상 분류
  → 54칸 상태 검증
  → cube_state.json 저장
```

## 사용 모델

이 프로젝트는 다음 저장소의 `cube-detector.pt`를 사용합니다.

- 모델 저장소: <https://github.com/2026-HBNU-Capstone-Robot-Muscle/cude-detector>
- 모델 유형: YOLO OBB (Oriented Bounding Box)
- 클래스: `side` 1개

모델은 큐브 면의 위치와 기울기만 탐지합니다. 색상 분류와 3×3 칸 분할은 본 프로젝트의 후처리 로직이 담당합니다.

Python 3.10 이상을 권장합니다.

### 기본 실행: Space 키 수동 캡처

```powershell
python main.py
```

카메라 화면에서 안내하는 면을 정면에 둔 뒤 `Space` 키를 누릅니다. 품질 검사를 통과하면 현재 프레임에서 면 탐지, 색상 추출, 저장이 자동으로 수행됩니다.

### 권장 실행: 새 출력 폴더 사용

```powershell
python main.py --output captures_run1
```

### 캡처 후 방향 확인 모드

```powershell
python main.py --confirm-capture
```


## 키 조작

| 키 | 기능 |
|---|---|
| `Space` | 현재 프레임 캡처 및 자동 인식 (기본 모드) |
| `Q` | 종료 |
| `0` ~ `3` | 확인 모드에서 면 방향을 시계 방향 0/90/180/270도로 보정 |
| `A` 또는 `Enter` | 확인 모드에서 캡처 저장 |
| `R` | 확인 모드에서 현재 면을 저장하지 않고 재촬영 |
| `F`, `R`, `B`, `L`, `U`, `D` | 최종 검증 실패 후 해당 면을 제거하고 재촬영 |

## 큐브 회전 안내 기준

스캔 시작 전 기준 자세를 정합니다.

```text
카메라 정면의 면 = F (Front)
그 상태의 위쪽 인접 면 = U (Up)
사용자 기준 오른쪽 면 = R (Right)
```

이후에는 개별 큐브 면을 돌리지 말고 큐브 전체만 회전합니다.

```text
F: 앞면 촬영
R: 왼쪽으로 90° 회전
B: 왼쪽으로 90° 추가 회전
L: 왼쪽으로 90° 추가 회전

U: 왼쪽으로 90° 더 돌려 앞면 자세로 복귀
   → 아래로 90° 회전하여 윗면 촬영

D: 윗면 촬영 자세에서
   → 아래로 180° 추가 회전하여 아랫면 촬영
```

카메라 화면에는 다음에 촬영할 면과 회전 안내가 영어로 표시됩니다.

```text
Next face: Right (R) | 1/6
Turn cube LEFT 90 deg: RIGHT face toward camera
SPACE: capture & recognize | Q: quit
```

## 출력 파일

기본 출력 폴더는 `captures/`입니다.

```text
captures/
├── F/
│   ├── original.png      # 캡처 당시 원본 프레임
│   ├── warped.png        # 원근보정된 큐브 면
│   ├── debug.png         # 원본 YOLO OBB와 보정 3×3 격자를 결합한 확인 이미지
│   └── metadata.json     # OBB, BGR/Lab, confidence, 회전값 등
├── R/
├── B/
├── L/
├── U/
├── D/
└── cube_state.json       # 검증 통과 시 생성되는 최종 54칸 상태
```

`cube_state.json`의 핵심 구조는 다음과 같습니다.

```json
{
  "face_order": ["F", "R", "B", "L", "U", "D"],
  "labels_by_face": {
    "F": ["F", "R", "... 총 9개"],
    "R": ["... 총 9개"]
  },
  "center_colors_bgr": {
    "F": [B, G, R]
  },
  "validation": {
    "is_valid": true
  }
}
```

## 3D 뷰어 (선택 사항)

3D 뷰어는 인식 결과를 사람이 확인하거나 시연하기 위한 기능이며, 큐브 상태 인식과 로봇 제어에는 필수는 아닙니다.

검증이 통과한 상태에서 `Q`를 누르면 자동으로 실행됩니다. 수동으로 실행하려면 다음 명령을 사용합니다.

```powershell
python viewer_server.py
```

브라우저에서 아래 주소를 엽니다.

```text
http://127.0.0.1:8000/viewer.html
```

## 검증 방식

색상은 고정 RGB 임계값으로 분류하지 않습니다.

1. 캡처한 6개 면의 중앙 스티커 BGR 값을 세션 기준색으로 사용
2. 모든 스티커와 기준색을 OpenCV Lab 색공간으로 변환
3. Lab 유클리드 거리가 가장 가까운 기준색으로 분류
4. 색상별 개수가 정확히 9개인지 검사
5. 1순위·2순위 색상 거리 차가 작은 스티커를 애매한 칸으로 기록
6. 6개 중심색 간 Lab 거리가 너무 가까우면 경고

색상별 개수가 맞지 않거나 중심색이 지나치게 유사하면 `cube_state.json`을 저장하지 않고 재촬영을 유도합니다.

## 제한 사항 및 향후 개선

- 현재 OBB 꼭짓점은 회전 직사각형이므로, 큐브 면을 크게 기울이면 실제 사다리꼴 경계와 오차가 날 수 있습니다.
- 정확도 향상을 위해 OBB 내부 윤곽선·직선 검출로 실제 면 꼭짓점을 보정할 수 있습니다.
- 여러 안정 프레임의 색상 중앙값을 합치면 조명·노출 변화에 더 강해집니다.
- 색상별 9개 검증은 통과해도 일부 스티커가 서로 바뀐 상태일 수 있습니다. 솔버 연동 전에는 엣지·코너 조각 조합까지 검사하는 큐브 물리 상태 검증이 필요합니다.
- 로봇이 큐브를 찾아 잡으려면 색상 상태와 별도로 카메라 캘리브레이션, `solvePnP` 등을 사용한 3D 위치·자세(6DoF) 추정이 필요합니다.
