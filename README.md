# 프로젝트: 큐브 면 인식 → 3D 모델 변환 프로그램

## 목표
로봇이 3x3 큐브를 손으로 잡고 돌리는 동안, 카메라가 각 면을 실시간으로 자동 인식·캡처하여
6면(54칸) 색상 상태를 3D 모델로 시각화하는 프로그램을 만들려고 한다.
(솔버 연동, 로봇 제어 명령 생성은 이번 범위에서 제외 — 3D 모델 출력까지가 목표)

## 사용할 모델
https://github.com/2026-HBNU-Capstone-Robot-Muscle/cude-detector 의 cube-detector.pt 사용
- YOLO OBB(Oriented Bounding Box) 모델, 클래스는 'side' 1개뿐 (실제 로드해서 확인함: task='obb', names={0:'side'})
- 이 모델은 큐브 면의 위치+기울기(xywhr 기반 회전 직사각형)만 탐지함
- 색상 분류, 9칸(3x3) 구분은 모델이 하지 않음 → 후처리로 직접 구현해야 함
- 주의: OBB가 반환하는 4개 꼭짓점은 "회전된 직사각형"의 꼭짓점이지, 카메라가 비스듬히 볼 때
  생기는 실제 면의 "사다리꼴" 경계와는 다를 수 있음 (기울기가 클수록 오차 커짐)

## 환경/제약
- 로봇 아직 미완성 → 지금은 사람이 손으로 큐브를 움직이며 테스트하는 프로토타입 단계
- 카메라는 노트북 내장캠 사용 (추후 휴대폰 IP 스트리밍으로 교체 가능성 있으니 카메라 소스 부분은 분리해서 설계)
- Python 3.10 이상 필요 (타입힌트 문법 사용 예정)

## 확정된 파이프라인
1. 카메라 스트림 시작 (camera_source.py로 추상화)
2. 매 프레임 cube-detector.pt로 면 ROI 탐지 (위치+각도, OBB)
3. 정지 판정 — 최근 N프레임 동안 탐지된 면의 중심좌표가 거의 안 움직이면 "정지 상태"로 판단
4. 정지 상태 + 아래 캡처 품질 조건을 모두 만족할 때만 자동 캡처
   - YOLO confidence 임계값 이상
   - 면의 픽셀 면적이 최소 기준 이상
   - 4개 꼭짓점이 화면 밖으로 잘리지 않음
   - 정면성(frontalness) 추정용 OBB 종횡비가 최소 기준 이상 (거친 프로토타입 필터이며,
     실제 원근 기울기를 정밀 측정하는 것은 아님에 유의)
   - Laplacian variance >= 최소 선명도 임계값 (값이 낮을수록 블러이므로 "이상"으로 체크)
   캡처 성공 시 화면에 "N/6면 캡처됨" 표시
   - 캡처 직후 잠금 상태로 전환 (같은 면 중복 캡처 방지)
   - 화면에서 면이 사라지거나 크게 움직이면 잠금 해제 (다음 면 캡처 대기)
5. 원근보정 (2단계로 구분해서 구현)
   - 1단계(프로토타입): 면을 카메라에 최대한 정면으로 보여주는 조건 하에, OBB 꼭짓점만으로
     원근보정(Homography)
   - 2단계(정확도 개선, 추후): 기울어진 면까지 정확히 처리하려면 OBB로 ROI만 잡고,
     그 안에서 윤곽선/직선검출(Hough line 등)로 실제 사다리꼴 꼭짓점을 보정하는 단계 추가
6. 3x3 격자로 분할, 각 칸 중앙 부분(가장자리 14% 제외)의 중앙값(median) 색상(BGR) 추출
7. 6면 모두 캡처될 때까지 3~6 반복
8. 54칸 색상 데이터 조립 + 검증
9. 3D 모델로 렌더링 (Three.js 기반 로컬 웹 뷰어, 최종 결과물)

## 중요 설계 결정 (반드시 반영)

### 꼭짓점 순서(핸드니스) 처리 — 실제 버그로 확인된 사항
- 모델이 반환한 4개 꼭짓점의 "첫 번째 점"은 그대로 유지해야 한다.
- 단순히 각도 기준으로 `argsort` 재정렬하면 안 된다 — 이 경우 원본 첫 점과 무관하게
  "각도가 가장 작은 점"이 새로운 시작점이 되어버려서, 면이 화면에서 잡히는 절대적인 회전
  각도에 따라 시작점이 바뀌는 버그가 생긴다 (실제 테스트로 재현 확인됨).
- 올바른 처리: 첫 번째 점은 고정한 채, 나머지 3개 점의 순서가 원하는 핸드니스(예: 시계방향)와
  반대일 때만 그 3개 점의 순서를 뒤집는다 (첫 점 기준 상대적 방향만 통일, 시작점 자체는
  절대 바꾸지 않음).

### 캡처 원본 및 메타데이터 보존
각 면 캡처 시 다음을 모두 저장:
- 원본 프레임
- OBB 및 보정된 꼭짓점
- 원근보정 이미지
- 9칸 원시 BGR/Lab 값
- 캡처 시각, confidence, 면 이름, rotation_quarter_turns
→ 나중에 색상 분류 로직만 개선해도 재촬영 없이 재처리할 수 있도록

### 색상 분류 방식
- BGR 유클리드 거리가 아니라, `cv2.COLOR_BGR2LAB`로 변환한 Lab 공간에서의 유클리드 거리로
  분류한다. 기준색(6면 중심색)과 샘플색(각 칸) 모두 동일한 `cv2.COLOR_BGR2LAB` 변환을
  일관되게 적용해야 거리 비교가 의미 있다.
- 고정 절대값 기준이 아니라, 이번 세션에서 실제 캡처된 6면의 중심(center) 색을
  기준색으로 삼아 상대적으로 가장 가까운 색에 매칭 (세션 캘리브레이션)
- 분류 후 다음을 함께 기록:
  - 색상별 개수 (정확히 9개인지)
  - 각 칸의 1순위·2순위 후보 색상 간 Lab 거리차 (작으면 "애매한 칸"으로 표시)
  - 6개 중심색이 서로 충분히 구별되는지 (Lab 거리 기준)
- 개수가 9개로 안 맞으면 자동으로 억지 보정하지 말고, 의심되는 칸/면을 표시해서
  재캡처를 유도할 것

### 캡처 트리거
지금은 자동(정지 감지 + 품질 게이트) 방식이지만, 나중에 로봇 신호 기반으로 교체할 수
있도록 트리거 판단 로직은 별도 함수/모듈로 분리해서 설계할 것

### 면 순서 및 방향(회전) 관리
- 6면은 사람이 정해진 순서(예: F→R→B→L→U→D)로 큐브를 돌려가며 보여준다고 가정.
  이 순서를 사람이 놓치지 않도록, main.py 화면에 "지금 보여줄 면: Front" 식으로 다음에
  찍어야 할 면을 안내하는 UI를 넣을 것
- [실제 테스트로 확인된 이슈] 정사각형 면은 90도 회전해도 형태가 동일해서, 모델이 준
  4개 꼭짓점만으로는 면의 실제 방향(0/90/180/270도)을 구분할 수 없다. F→R→B→L→U→D
  순서만으로는 각 면의 3x3 방향까지 완전히 확정되지 않음.
- `rotation_quarter_turns` 정의: "원근보정 이미지 기준으로, 해당 면을 표준 방향으로
  만들기 위해 시계방향으로 적용해야 하는 90도 회전 횟수(0~3)". 이 정의를 코드/문서
  전체에서 일관되게 사용할 것.
- 캡처 메타데이터에 face_name뿐 아니라 rotation_quarter_turns도 저장.
  초기 버전에서는 캡처 직후 화면 미리보기로 사용자가 방향을 확인·보정할 수 있게 UI 제공

### 중복 면 방지
캡처 슬롯을 F, R, B, L, U, D로 명시적으로 관리하고, "면이 사라지거나 이동하면 잠금 해제"는
재캡처 방지일 뿐 실제로 다른 면이라는 보장은 아님에 유의. 새 캡처의 중심색을 이전에
캡처된 슬롯들의 중심색과 비교해서 유사하면 "중복 의심" 경고를 표시할 것

## 원하는 모듈 구성
1. face_tracker.py — cube-detector.pt로 면 탐지 + 정지 판정 + 캡처 품질 게이트
2. color_extract.py — 원근보정 + 3x3 분할 + 색상(BGR) 추출
3. camera_source.py — 내장캠(인덱스 0)과 휴대폰 IP 스트림 URL을 동일한 인터페이스로
   다루는 카메라 추상화 모듈
4. cube_state.py — Lab 색공간 기반 세션 캘리브레이션 색상 분류 + 54칸 상태 조립 + 검증
   (색상 개수, 애매한 칸, 중심색 구별도 체크 포함) + 원본/메타데이터 보존 구조
5. main.py — 카메라 루프, 면 순서/방향 안내 UI, 진행상황 표시, 완료 시 3D 렌더링 호출까지
   전체 오케스트레이션
6. 3D 뷰어 — Three.js 기반 로컬 웹 뷰어. 완성된 54칸 상태를 마우스로 회전/확대 가능한
   3D 큐브 모델로 렌더링, 54개 스티커 색과 면 이름을 명확히 표시
